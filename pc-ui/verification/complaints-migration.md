# 投诉处理迁移及流程优化验收

日期：2026-10-22。入口：`pc.html#complaints`。业务源码：`pc-ui/complaints.js`；结构样式：`pc-ui/complaints.css`。对应 PC 规范 v1.10。

## 范围与运行方式

从 index.html 内嵌的统一投诉处理迁移业务，保留三渠道、18 条投诉、22 笔关联订单及完整处理流程。仅修改 PC 入口，未引入原入口 CSS、导航或 iframe。构建后的 pc.html 单独复制到临时空目录，通过本地 8767 端口查看；该目录只有 pc.html，不依赖 index 或业务源目录。验收记录仅写入临时预览来源的 localStorage，不操作实际客户、支付或外部消息。

PC 数据键为 `weid.pc.complaints.v1`；同源首次可读原入口数据，后续独立存储。不同域名或 file 来源不承诺自动迁移本地记录。

## 追加操作布局验收

- 投诉渠道单元格移除内部工单号，保留渠道、投诉时间及微信金额摘要；详情仍保留识别工单所需编号。
- 回复客户采用真实布局容器置于详情底部左侧，实测按钮距抽屉左边界约 16px；点击正常打开回复抽屉。
- 写跟进入口移至跟进记录 Tab 内容区顶部右侧，处理方案 Tab 及公共底栏均不显示；新增跟进返回后保留跟进记录 Tab，已结案同样可打开写跟进。
- 开始处理但未保存方案的工单没有结案按钮；新增普通跟进后仍无结案按钮。已有方案的处理中工单仍能打开结案确认，取消保持状态。
- 新增两项业务边界测试，确认不能绕过 UI 结案，保存时间 / 历史方案兼容，待处理与已完成不可重复结案。
- 最新界面：[操作位置与结案入口](./complaints-follow-actions.jpg)。此前尺寸截图保留为布局测量记录，按钮位置以本图为准。
