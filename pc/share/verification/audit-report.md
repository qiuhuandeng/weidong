## 已修复的问题

1. 搜索条件过密：公共内边距 16px 20px、行距 12px、列距 24px、独立按钮行上方 16px；按容器宽度三 / 两 / 一列，窄抽屉不再压扁输入框。
2. 门店等选择器、表格批量选择遗留原生单选 / 复选框：统一为 Element Plus，并验证单选互斥与批量勾选。
3. 公司表格后代 span 样式压扁选择指示器：公共主题保持 14px × 14px 方框 / 圆点，实测显示正常。
4. 混合布局中的独立表单未挂载 ByForm：按连续字段组接入，保留说明及规则树顺序。
5. 门店指引视频切换 / 关闭报错：业务字段采集器不再把公司表格列节点当成表单字段；未选中的 radio 不进入模型。
6. 退款筛选与床位日期事件遗留在外层 div：旧 form 的 ID / input / change / submit 事件全部迁至真正 ByForm 表单，FormData 正常读取。
7. 床位日历把条件组挤入一个栅格，并把日期快捷项误当操作行：拆开条件、恢复搜索 / 重置独立行。
8. 批量床位的原生月份框替换为 ElDatePicker month；旧百分比列宽不再误转为像素。

## 验证结果

- 15 个主模块在常规宽度与 1280px 均无页面横向溢出、可见原生字段遗漏、嵌套 form；1440px / 1024px 多条件列表回归通过。
- 所有主搜索区实测 row-gap=12px、padding=16px 20px，均存在“重置 / 搜索”；日期快捷项独立存在。
- 门店关键词 Enter 筛选得到 1 条，重置恢复 20 条；退款主管“待审核”筛选得到 1 条，展示可用的通过 / 拒绝入口。
- 单选 15 / 30 分钟切换后原兼容字段互斥正确；二级城市确认后保留父级临时介绍，父级取消后重新打开介绍为空；原门店资料保存成功。
- 公司表格中的 checkbox / radio 指示器最终实测均为 14px × 14px。
- 本轮发现的两类运行错误已修复并回归。audit-console.json 保留发现时的历史错误，最终修复后的操作无新增错误。
- pc.html 在只含该文件的临时目录运行；未引用外部 script / stylesheet。全脚本语法检查、依赖校验及 git diff --check 通过。
- index.html SHA-256 保持 67d8ebc9e0ca9a125ee14aae4d010dcd5b135523e090449775d655e639b11621，未被本轮修改。

## 条件入口和明确边界

- 当前默认日期内有主管待审核示例；售后 / 财务待审核筛选为空，人工转账筛选也为空，相应按钮禁用。因此未声称这三个状态的业务提交已执行。它们复用同一审核 / 确认结构，源码已核对；补充对应示例数据后仍需按本规范回归。
- 门店示例没有有效地图链接及可预览的视频文件。地图入口显示缺失链接校验；图片 / 视频上传保留浏览器文件选择机制，不上传虚构文件。隐藏 type=file 是上传实现，不是可见组件遗漏。
- 未触发真实支付、生产审核、删除提交或外部上传；本地业务保存验证仅发生在隔离预览中。删除、解绑及审核的确认界面已打开检查，最终提交取消。
- 日历、仲裁条件树和合并单元格对比表按业务专用结构保留，内部基础控件使用公司体系；移动预览保持独立移动端规范。
