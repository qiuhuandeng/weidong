适用范围与优先级

本规范是 pc.html、inventory.html 及后续 pc-<业务>.html 共用的 PC 现有页面、各层弹窗与抽屉，以及后续新增页面的正式 UI 实现依据。视觉基准是当前用户已确认的 PC 页面：保留其颜色、密度、搜索区、内容区、操作按钮、控件和抽屉规格，通过本规范与本地公共实现统一维护。运行时采用原生 HTML / CSS / JavaScript，独立于其他原型入口的 UI 标准。原生实现不意味着每页重新设计控件。

已确认视觉的历史参考来源：公司组件文档。公司文档及旧 公司门店列表 仅作补充参考，不能覆盖当前本地标准，不因网站示例或版本变化调整已有页面，也不引入其中的运行库、安装命令或框架 API。遇到旧页面局部差异，按本规范与公共实现修正，不能把任意单页差异升级为新标准。

运行时从 1.31 起移除 Vue、Element Plus、公司组件包、VXE 和图标字体依赖。用户已确认以原生实现替换运行库，同时要求现有页面功能和样式保持。公司文档继续作为视觉参考；不再要求实例化第三方组件，不使用虚假的 By* 导出冒充旧库。

优先级：当前用户明确要求 → 本规范及 share/ 公共实现 → 本目录 业务约束.md 的业务约束。旧规范中的 150px 侧栏、56px 顶栏、16px 页面留白、无标签搜索、白色搜索按钮、上置标签门店表单等视觉规则不再适用于 pc.html。业务规则、审核边界、数据含义和草稿机制继续保留。

仓库根目录 index.html 只负责导航；中台与 V3 分别遵循各自项目内的规范及已确认实现，不引入 PC 的 share/，不参与此构建。H5 及移动预览也不因本规范变更主题。不要用 pc.html 覆盖任何其他入口。仅修改 PC 时，应对比导航、中台与 V3 入口的 SHA-256，确保未动其内容。

在统一 UI 规范下遵循最小改动范围：

  • 普通文案、字段、数据、业务流程和现有组件参数调整，默认只改 share/pages/<业务名>/ 内对应业务源码，优先复用已有组件、样式和变量；按现行规范修正页面实现也不顺带改公共层、无关页面、构建工具或配置。

原生实现与依赖边界（强制）

  • PC 主入口、进销存、后续独立入口及其内部页面统一采用原生 HTML / CSS / JavaScript。禁止新增或恢复 Vue、Element Plus、公司组件运行包、VXE 及其他第三方前端运行库；下载到本地、复制进源码或内嵌进 HTML 同样属于引入依赖，不因离线可用而例外。
  • “无依赖”指没有第三方运行依赖，不是每页都写成单文件。继续复用自写的 PCUI、系统壳层、设计变量与公共 CSS，业务按需加载，不复制公共实现，不将所有业务重新打成一个大包。保留现有字段、流程、数据、草稿和视觉规格。
  • 字体使用操作系统字体，图标使用现有内联 SVG。禁止字体包、图标字体、@font-face、远程脚本与远程样式；不能从 CDN 加载，也不能把旧包换一个文件名重新打入发布目录。
  • 新业务通过 routes.json 登记本地 JS / CSS；按需功能通过 PCApp.loadModule 加载。仅公共 bootstrap.js / loader.js 负责插入资源，业务不得自行拼装 script / link、使用动态 import 或另一套包加载器。为纯逻辑测试保留的 CommonJS 分支只可引用已有的本地相对文件。
  • build.py 在生成发布文件前检查运行源码与入口模板，拒绝禁用 UI 全局、包导入、vendor / node_modules 资源路径、脚本 / 样式标签引用、业务插入脚本 / 样式、CSS import、远程 CSS 资源和字体声明，错误包含来源与原因。该检查与体积预算一起执行；不能关闭检查或抬高预算来恢复依赖。静态检查不能代替对新增源码的审查，复制或混淆第三方代码仍被规则禁止。
  • 公司文档仅供视觉参考，旧验收记录仅供历史追溯。若其中提到实例化旧库、安装包或加载字体，以本节与当前原生组件目录为准，不按旧记录重新接入。share/verification/ 不属于现行规则或运行资源。
  • 业务链接、用户附件和富文本中的媒体地址不等于 UI 运行库，不为了消除外链字样删除已有业务功能。开发检查可以在临时环境使用测试工具，但不得将其依赖打入网页或作为页面打开的前置条件。

公共交互与数据契约

  • 基础字段保留原 DOM 对象，不克隆业务字段或重新绑定一套业务状态。选择和日期的原字段仅作为值源，隐藏且退出 Tab 顺序；标签指向可见控件。PCUI.syncControl(element) 同步程序修改，PCUI.focusControl(element) 聚焦可见入口。重置表单后自动同步显示。
  • PCUI.sweep() 增强新增 DOM；PCUI.whenReady() 在本轮增强后继续。主页面、抽屉、弹窗由公共观察器处理；宿主离开时清理观察器与浮层，重复 sweep 不重复包裹或绑定。
  • 菜单按空间显示在触发器附近，选中后恢复触发器焦点再执行原动作。Escape 先关闭浮层，不连带关闭父抽屉；业务键盘监听先检查 PCUI.isPopupOpen()。
  • 层级多选持久化叶节点值；全选子树时右侧汇总父节点，支持搜索、批量名称、搜索结果全选、逐项移除、清除。名称按换行、逗号、分号、空格分隔，匹配任一名称。
  • 层级容器大于 960px 时右侧显示已选项，不超过时移至下方，最多 140px 后内部滚动；多级列保持可横向滚动，搜索仍固定 280px。
  • data-pc-table-name 启用列宽记忆与重置，沿用已有存储键和 {field:'c0',width:...} 数组。读取 / 保存失败显示原因并保留原存储，不清空数据。
  • 富文本最小高度 240px，工具栏保留撤销、重做、文字格式、段落、链接、图片、本地图片、表格、代码、锚点、媒体、表情、分页符、日期时间、查找替换、源码、预览、全屏。操作记忆并恢复选区；禁用或只读禁止修改。图片仅 PNG / JPEG / WebP，单张最多 2 MB，读取失败保留正文；不自动上传。HTML 清理脚本、事件与不安全链接，媒体仅 http(s) 地址，不执行 iframe。
  • 新页面交付说明实际使用的公共入口与完成的关键交互检查；不能以“已加载 PCUI”代替功能检查。不默认保存验收截图或报告。

默认紧凑密度

按用户 2026年10月22日的反馈，pc.html 全部现有页面与后续新增页面默认采用紧凑密度。已确认的颜色、尺寸、结构与交互继续沿用，控件由原生 PCUI 实现，官网演示的普通大尺寸不直接作为原型默认值。统一使用下表中的字号、控件、行距和间距；不通过浏览器缩放、CSS zoom 或 transform 缩小整页，也不只给单个业务追加密度样式。

密度变量集中在 share/css/tokens.css 的 --pc-font、--pc-control、--pc-search-control、--pc-table-line、--pc-table-padding、--pc-form-gap 和 --pc-gap。公共原生组件使用对应尺寸变量；不得恢复 large 表单或 14px 大列表作为默认。

紧凑控件与搜索区留白分别管理。搜索区使用 --pc-search-padding、--pc-search-row-gap、--pc-search-actions-gap、固定字段宽度 --pc-search-field-width:280px 和公共搜索布局的 24px 列间距；禁止为压低整块搜索区而取消条件行距或挤压按钮行。

列表与搜索

有业务 tab 时执行上方“全页面统一 Tab”，紧邻搜索区域。搜索与表格内容分为两块白底区域，间隔 12px。页面顶部、左右边距与该间距一致，均使用 --pc-gap:12px；首屏 critical CSS 与完整主题保持相同规格。旧兼容 CSS 不再以 !important 固定搜索区下方 16px；内容 tab 与搜索区仍为零间隔。

搜索条件采用公司后台的横向标签：标签在控件左侧，以“：”结束，不在控件上方加标题。标签应描述条件本身，例如“状态”“城市”“申请日期”，不要写成程序变量名或重复“全部”。搜索使用公共原生布局，由当前搜索区最长标签统一决定该搜索区的标签列宽；标签 13px 字号、32px 行高、右侧间距 8px、单行显示。短标签页面不再统一预留 120px，例如门店床位的标签列宽为 60px（含右侧间距）；不得给所有搜索区强加过宽标签列，也不得让各字段分别自定标签宽度。内部输入和下拉保持 28px / 12px 的 mini 视觉尺寸。

普通搜索控件区域固定为 280px，由公共变量 --pc-search-field-width 管理；输入、下拉、单日期、选择按钮和组合关键词均遵循此宽度。日期范围及展开式状态选项组按下方专用宽度规则执行，不能机械套用 280px 导致选项折行。每项总宽为本搜索区统一标签宽 + 当前控件固定宽度，项间保留 24px。按业务顺序从左向右排布，空间不足时整项换行；不再采用百分比均分或固定三 / 两 / 一列断点。宽屏自然容纳更多条件，剩余空间留在行末，不能靠放大控件填满。主页面与各层抽屉都按自身可用宽度自然换行；只有单项仍放不下的极窄容器，才允许普通输入收缩防溢出，展开选项组则切换为下拉。

对齐是公共组件的强制要求，不只检查间距。 同规格条件的标签与控件边界保持一致，同一行的第一排控件顶部对齐。日期组合及宽档状态组完整占用自身宽度，不挤压相邻输入或强行与 280px 控件对齐右边界。组件不随页面宽度伸展；内部允许填满自己的固定容器，禁止直接按页面或百分比栅格设置 100% 宽。清除旧页面 160px / 240px 等冲突宽度及 max-width。选择按钮的文字靠左、箭头靠右；组合关键词整体 280px，类型选择器 112px、间隔 8px、输入框 160px。公共搜索 form 本身采用占满容器的块布局，不继承原搜索 form 上的旧 grid / flex 排版。

需要跨行按列对齐时，在搜索 form 上声明 data-pc-query-align="columns"，由公共 PCUI.query 计算能容纳的列数及每列所需宽度。同一列的标签与控件左边界对齐，列宽取该列条件的最大固定宽度；较短控件保留原宽度，余量留在该列内。条件仍按业务顺序排列，不设置空白占位、百分比均分或页面专用断点；容器变窄时自动减少列数，极窄时整项收缩。当前投诉处理主搜索启用，未声明的搜索区保留原有自然换行布局。

表单与基础控件

普通门店 / 规则配置字段及夹在说明、条件组、表格之间的独立字段均使用公共 .pc-form 分组，保留原表单和业务字段。标签右对齐，默认宽 110px，控件高 32px，标签字号 13px。短字段双列、列间距 16px，长文本通栏，行间距 14px；简单窄抽屉使用单列；多行文本域最小高度 64px，按内容增高。

公共控件的基础校验不代替业务校验。保留原来的必填、范围、审核条件、只读及禁用逻辑；不要为视觉统一加新的隐藏门槛。保存成功才写入当前业务数据；取消不提交当前层草稿。

  • PCUI.syncControl(nativeControl) 同时支持已接入的复选、单选、开关与日期控件。批量勾选或程序回填后先更新保留字段的 checked / value，再调用该入口同步可见组件；不额外派发业务变更事件，避免重复保存。集团审批的人员快捷选择与统一字段权限复用此能力。

  • 独立业务分页用 PCUI.registerPager(action, callback) 注册，data-pc-pager 传入 total / page / size / action 及业务 scope；禁止跨模块修改 UB 状态凑用分页。
  • 原表格单元格和业务 data-* / aria-* 保留不变，金额小计等更新定位仍有效。业务列最低可读宽度通过 th 的 data-pc-min-width 声明，窄屏只在表格内横向滚动，不把长内容列压成过窄竖列。多行信息使用公共 pc-block，多行文字操作用 pc-multiline；不能依赖旧库的 span 默认显示，也不能让固定按钮高度压住多行文本。空表保留业务提供的空态文案。表格可用 data-pc-align="left|center|right" 指定表头与内容对齐，未声明继续默认居中，不允许用单页强制 CSS 覆盖对齐。
  • 少量明细行的抽屉表格可在原始 table 上声明 data-pc-min-height="0"，由 PCUI 设置原生表格滚动区 min-height，随内容收缩，避免单行下方留出空白；退款项目与商品置换抽屉已使用。默认最小高度仍为 160px，未声明的表格保持原尺寸；不通过业务 CSS 覆盖公共表格高度。
  • PCUI 表格适配器支持显式通栏行：tbody > tr[data-pc-full-row] 内仅放一个 td，其 colspan 等于列数。公共增强保留原生合并单元格，用于订单分组和表内汇总；普通行不变，未标记的任意跨行 / 跨列表格仍不自动转换。不使用厂商表格合并 API。
  • 表头全选复选框可用 data-pc-indeterminate="true" 声明部分选中，公共适配器透传到原生 checkbox.indeterminate；勾选变化后重绘时重新计算该值，不手绘半选图标。
  • 自动挂载按钮、输入时保留当前焦点；业务重绘后校验、关闭与键盘 Tab 的焦点不能落到不可见原字段。

新增与修改页面的做法

  1. 读取本规范及业务约束，定位 share/pages/<业务名>/ 源码；新模块优先通过 new_page.py 创建。先在组件目录中确定搜索区、内容区、操作、表格、分页、表单与抽屉各自的公共入口，沿用当前已确认页面的视觉，不从旧业务复制一份主题。
  2. 业务输出原生结构，PCUI 只增强控件；保留事件、字段、状态和原数据。标准列表使用下文公共组合，不另写搜索布局、按钮皮肤、表头或分页控件。对齐、列宽、表单列数等差异使用已有参数；独有业务布局才增加局部结构样式，不覆盖公共控件。不要新增 Vue 宿主或恢复旧厂商引用。
  3. 动态内容放在 #main、#mergeDrawers 或 #modal 内；观察器自动增强，移除时清理控件观察器与浮层。特殊布局通过明确边界排除重复增强。
  4. 新增通用能力改公共源码并同步规范；普通业务修改不顺带调整公共层。按影响范围实测搜索固定宽度和换行、内容间距、按钮状态、表格长文本与空态、抽屉宽度与滚动；涉及交互时检查搜索 / 重置、分页、校验、键盘、父子草稿和关闭后焦点。依赖与体积检查不能代替视觉和交互检查；未涉及的控件不要求全站回归。
  5. 仅更新发布资源时运行构建；不手改 HTML 和 dist。临时验证产物用完即删，交付简述实际检查结果。

“全局”仅指 PC 系统内全部页面：一个或多个 PC HTML 入口都通过同一模板、同一组件适配器和同一主题构建。index.html、zhongtai.html、v3.html 不引入这些资源；中台与 V3 分别位于同级 zhongtai/、v3/ 子项目，各自维护自己的入口、资源和规范。

  • templates/entry.html 是所有 PC 入口的唯一壳层模板；css/critical.css 与 css/tokens.css 提供首屏加载反馈，完整主题就绪后保持相同视觉。
  • js/bootstrap.js 统一预加载当前模块、递归依赖及所需公共资源，由构建内联到入口；js/core.js / js/loader.js 只处理共享工具、导航、加载去重与生命周期，不维护第二套预加载清单。
  • pages/customer/index.js 与 pages/management/index.js 保留原互相关联的业务与草稿，不在目录迁移时重写。独立新业务必须新建 pages/<业务名>/，不能继续塞进这两个兼容文件。
  • 模块用闭包封装状态，经 window.PCModules[模块名] 暴露 render()、可选 redraw() 与 leave()。离开时释放自己的监听、定时器、请求和弹层；不能复制导航、另绑 hashchange 或增加业务全局变量。
  • routes.json 只登记本模块目录的 JS / CSS；构建拒绝跨模块引用、引入第三方运行包、重复路由与超过预算的模块。通用 UI 能力放公共 UI 层；共享库存账等领域能力保留在独立业务模块，通过依赖声明复用，不塞入 components.js 或 core.js。
  • 模块默认 requiresUI: true，所有表单、列表与交互控件使用公共原生组件。静态壳层页面（当前为欢迎首页）可显式登记 requiresUI: false，只加载公共壳层样式与本模块；首次进入业务再加载原生组件脚本。快速切回首页不等待正在下载的业务依赖。
  • 公共加载器固定样式顺序为业务基础 → 公共主题 → 模块结构样式；首次直达、欢迎页进入业务及失败重试都保持该顺序，不能让网络先后或首次访问页面决定层叠结果。回归须比较直接进入业务与从欢迎页进入时的控件布局。
  • 加载器按依赖图等待公共组件、业务依赖及其 ready 成功后，再执行本模块。并发请求共用一个 Promise，重复进入不重复执行脚本；只有当前导航可渲染或展示错误，慢业务加载期间返回首页不等待业务依赖。渲染成功后才标记页面就绪。
  • 不用固定秒数定时器判定脚本、样式或入口失败，不删除仍在下载的脚本。网络结果由浏览器 load / error 决定；真实传输失败可重新请求，脚本执行异常保留原始原因且本页不重复执行，避免重复声明或写入。重新加载按钮仅用于真实失败后的整页重建，不作为慢速首开的必要步骤。
  • 无路由的按需功能通过 PCApp.loadModule(模块名) 加载，仍登记在 routes.json，可只导出业务 API，不要求 render()；有路由的模块必须有 render()。投诉解决方案复用此入口，业务不得自行追加 script 标签、维护独立超时和加载缓存。
  • 专用 style.css 仅处理日历、业务信息排列等独有布局，选择器限于 .pc-page-<业务名> 等自身容器，注册后才随模块加载。不得覆盖 :root、body、通用按钮、.pc-* 公共控件、.el-* 或 .vxe-* 皮肤；不得用 !important 绕过公共规格。现有投诉结构类沿用 uc-*。
  • css/legacy-business.css 是旧业务兼容文件，处于低优先级 pc-business layer。目录迁移不拆散其相互依赖的规则；新增业务不得继续向这里追加样式。

新模块初始化与本地存储

  • 模块先同步注册，再通过 ready 完成异步数据初始化；公共加载器等待 ready 后渲染。新建模板已提供该入口，禁止在模块注册前直接写入业务存储。初始化失败须保留真实原因，允许重试或切换菜单，不能统一解释为网络故障。
  • 持续增长的审批、单据、附件等本地业务数据使用 IndexedDB；少量偏好仍可使用 localStorage，但读写必须处理容量与权限异常。不能因 localStorage 已满导致页面无法注册，也不能以清空浏览器、删除其他系统数据或静默重置示例数据作为修复手段。
  • 迁移只在目标库尚无数据时执行；优先读取本模块已有数据，再按明确的迁移关系读取来源数据。校验并成功落盘后才使用新库，保留原记录，不回写来源系统。格式不兼容或迁移失败时明确提示，不覆盖旧记录。
  • 保存成功以事务提交为准；提交前不更新已保存状态或提示成功，失败保留原账和当前填写内容。多窗口更新在同一读写事务内检查版本并提交，拒绝旧版本覆盖。更新通知与数据保存分开，通知失败不能误报已提交的操作失败。
  • 新增或修改持久化路径时，针对受影响模块验证：已有记录迁移、localStorage 写满、数据库不可用、写入失败、刷新保留及并发冲突；有多窗口入口时补同步检查。只在空存储下打开页面不算完成此项检查。普通文案和样式调整不因此要求全站回归。

进销存院内执行与记账约束

  • 治疗单以原系统患者 ID、来源订单及唯一治疗执行号关联，保留项目、BOM、价格与卡权益快照。领料预占、发料、指定人员签收、配台、独立复核、实际使用、余料处置与治疗核对分别留单据。科室备货只转移实物位置，不计服务消耗。
  • 开封、院内移库及退料是实物形态或位置变化，不减少机构总实物库存。治疗实际使用、报损销毁分别记流水和成本；按瓶登记 0 用量不得自动开瓶。追加领料保留原标准、医嘱依据和追加记录，已配台时须重新核对。实物使用已经发生的偏差先记实际账，后独立复核，不因审核再次扣库。
  • 每支物料保留容器码和来源链；生产批号追溯与单容器追溯区分。实际库位与客户归属分开；寄存仍在物理盘点范围，排除可售库存。未开封退库要独立验收，质量不确定转隔离；治疗单只有“领出 = 实际用量 + 退回 / 隔离 + 合规留存 + 已确认销毁”对平且相关复核完成后才能关闭。
  • 单次使用产品不得配置寄存或跨患者复用。允许留存必须来自已核准的具体产品依据和开封时限；系统不预设医疗剂量或通用留存时间。需要配制的剂量物料按单瓶记录原剂量、实测配制后体积、配制用液批号、医生确认依据后计算本瓶换算；不能将该换算写为所有同 SKU 通用的 ml 系数。开封到期锁定余量、解除相关临床预占并进入待复核处置，不直接删除实物。
  • 新采购使用多明细、分批和多批号验收；数量、采购单位、基本单位、送货凭据与发票核对分别保存。应付按实收入库减采购退货及已付款计算。调拨分批收货、破损隔离、短少责任认定与退回在途分别处理，不把差异自动当正常收货。
  • 盘点计划下发到多个实物批次，指定人员实盘、另一位人员复核；实盘之后的合法流水纳入库存调整校验。期初及新发现实物先经独立复核建账，再进入质量待确认。召回完成须同时处理实物、在途和已使用患者跟进任务；单纯把剩余库存清零不视为完成。
  • 当前办理账号、角色和机构范围用于本地原型的职责校验；正式接入需要服务端认证与权限。原订单、退款及付款采用凭据核对登记，不伪装为已执行外部支付或已自动同步。
  • IndexedDB 是本地唯一主账；保存时在同一读写事务中比较账本版本，拒绝其他窗口基于旧版本覆盖新账。无法使用 IndexedDB 时，仅在浏览器提供排他锁时回退 localStorage；容量或保存失败要保留原账、回退未落盘操作并明确报错。保留旧 localStorage 数据用于迁移，不在模块顶层大对象写入时阻断页面注册。

缓存与发布

构建使用内容 SHA-256 命名资源。只修改某个业务模块时，它的文件名变化；公共组件和其他业务文件名保持不变。share/dist/ 可长期缓存，HTML 每次校验更新；不添加随机时间戳清缓存，不依赖浏览器停用缓存，也不引入 Service Worker 接管其他系统。

发布仍可通过 Git 提交，由托管平台部署整个仓库。按用户确认，仓库根目录增加 vercel.json，仅对 /pc/share/dist/(.*) 设置 public, max-age=31536000, immutable；HTML 不使用该长期缓存规则，继续校验更新。新内容生成新文件名，部署后浏览器会获取新资源。配置依据 Vercel 响应头配置；本地新增文件不代表线上已生效，部署后须核对响应头。

PC 的 HTML 引用 share/dist/ 相对路径，能位于网站 /pc/ 子目录，也能单独部署 pc/ 为站点根目录。当前根配置按完整仓库部署编写；若单独部署 PC，须在实际部署根目录配置对应的 /share/dist/(.*) 路径，不能仅把配置放入任意子文件夹就认为平台会读取。中台、V3 与根导航不受这条 PC 缓存规则影响。

整站发布时保留 index.html 和三个完整子项目目录；PC 与进销存的运行包包含 pc.html、inventory.html 及同级 share/dist/，其余源码、工具和文档保留在本地维护。独立使用进销存时可仅带 inventory.html 与 share/dist/；需要兼容原 PC 进销存链接时同时发布两个入口。构建默认不主动删除旧哈希资产；按用户要求清理时，须核对当前资源清单、所有入口及运行源码的引用，只删除确认无引用的生成文件，不按目录名或文件时间判断。原生迁移后的旧版资源已完成该清理。share/asset-manifest.json 记录当前文件及体积；发布清理后的版本须同步更新两个 HTML 与资源目录，先前打开的旧版页面需刷新到新入口。正式 URL 为 /pc/pc.html 和 /pc/inventory.html，原根目录 /pc.html 不再保留实体入口；若需要兼容该旧根地址，需在托管平台配置到新地址的跳转。

性能门槛与新增验收

  • 构建会拒绝：入口超过 16,000 字节、共用资源 gzip 总量超过 100,000 字节、任何入口首次所需 gzip 总量超过 300,000 字节；新增独立模块（JS＋CSS）默认不超过 60,000 字节。现有客户兼容模块按迁移实测设为 180,000 字节，投诉模块为 40,000 字节；不能把这个例外用在新模块。
  • 超限应拆出非首屏功能、图片或数据，不能直接调高预算绕过检查。禁止重新打包 Vue / Element Plus / 公司组件库或外部字体；构建不得要求历史 vendor 文件存在。
  • 新增页面必须记录：冷缓存首开、普通刷新、第一次进入模块、第二次进入模块。相同环境使用 4 Mbps / 80 ms 作为固定对照条件，记录首屏出现与页面可操作两个时间，不能只用 HTML 体积宣称提速。
  • 验证新模块没有增加其他入口的请求；打开一个页面不会提前加载新模块；重复进入没有重复脚本与事件绑定。检查缓存复用、深链接刷新、前进后退、快速切换、资源失败后恢复，以及保存 / 取消 / 分层草稿。
  • 当前原生公共资源约 66 KB gzip，首页约 53 KB，投诉处理含业务依赖约 153 KB，进销存服务列表约 163 KB；以生成的 asset-manifest.json 为准。资源清单不含框架、厂商包和字体下载。本地 file:// 不产生外部资源请求；线上仍需从部署站点传输本站的 HTML / CSS / JS，不能保证任意网速下固定秒数。
  • 运行依赖已经移除，不再以取消超时或拆分厂商大包作为提速结果。验证必须覆盖业务功能、布局和首次加载，不能仅以文件缩小判定完成。
