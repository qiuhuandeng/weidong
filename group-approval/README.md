# 集团审批原型

已接入根 `index.html` 的“集团审批”菜单。原型包含工作台、审批列表、规则配置、组织与人员、审批统计和移动端演示；申请表、详情、审批/办理、消息和个人页面由统一路由承载。

## 使用入口

- 直接打开根 `index.html`，选择“集团审批”。
- 独立 PC：`group-approval/index.html#workbench`。
- 移动端：`group-approval/index.html?view=h5#workbench`。
- 建议 HTTP 预览：在仓库根运行 `python3 -m http.server 8769 --bind 127.0.0.1`，访问 `http://127.0.0.1:8769/index.html#group-workbench`。
- PC 与移动端统一固定为集团审批管理员（许宁），移除演示身份切换栏与当前处理人切换入口。打开页面会清理旧身份缓存；审批入口默认显示全部审批，可查看集团各公司的记录、规则、组织和统计。

文件协议与 HTTP 地址的浏览器存储相互独立，不会自动迁移；PC 与手机视图在同一浏览器、同一来源下共享数据。使用真实手机或另一台设备时，不共享此浏览器本地原型数据。

## 核心规则

- 内部员工是统一身份；钉钉主体身份按公司和用户标识关联。公司归属和管理组织分开。
- 流程支持指定人员、发起人本人、发起人自选、指定部门负责人、连续多级负责人、公司/集团岗位、直属上级、表单联系人、表单部门主管九种来源。指定部门的起点可选择固定部门或本次任职部门。
- 条件首个命中，默认分支兜底。表单字段参与真实匹配；发布校验防止失效字段引用。
- 草稿与发布版本分离。提交冻结表单、流程和解析后的任务。配置和组织后续修改不重写在途任务。
- 退回到发起人，修改后按本次冻结版本重新匹配并从头审批；之前的表单值、任务和条件路径保留为历史提交。
- 会签全部同意才前进，或签一人同意即前进，依次审批拆成顺序任务。抄送到达时自动执行，未到达的抄送不提前开放查看。
- 管理员有配置与授权范围内查看权限，不能以管理员身份直接替代当前审批人批准。转交、自审、重复审批、空人承接均有明确规则。
- 审批动作检查最新活动任务；多窗口使用 Web Locks 串行保存。规则编辑检查独立版本，防止覆盖另一窗口的修改。
- 附件单个不超过 1 MB，总计不超过 3 MB，本地保存并可下载。未提交内容离开时提供保存/放弃操作。

移动端独立使用 `mobile.css`，参照 `complaint-prototype/workflow/theme.css` 的色彩、卡片、标题和控件规范。统一浅灰页面背景、白色卡片、12px 圆角和轻边框；桌面预览保留 430px 页面边界。客诉原文件不作修改。

- 工作台、列表、发起、申请表和通知只保留顶部页面标题；去掉重复副标题、统计说明、申请页重复说明区和个人页原型说明，保留字段帮助、校验、退回原因和时限规则。
- 列表采用搜索栏与底部筛选面板；支持状态、公司、类型和日期组合筛选、取消及重置。空状态放在白色卡片内，无结果或只有一页时不显示分页按钮。
- 申请、详情、消息、个人页与操作弹窗共享字体、间距和按钮尺寸；窄屏日期控件自动改为单列。

## 节点时限与既有计时规则

入口：集团审批 → 规则配置 → 审批事项 → 流程设计 → 审批/办理节点 → 高级设置。独立“审批时限”页面及列表入口已移除，节点高级设置仍可配置处理时限、提醒与督办；既有整单计时配置和已发起申请继续按冻结版本执行。

- 每个审批/办理节点可启用或关闭时限，配置自然小时或自然天（24 小时），全天连续计时。暂不提供工作日历。
- 整单从提交到结束，包括办理和退回待修改时间；草稿不计时。退回重提可选择延续首次截止时间，或在重新提交时重置整单截止时间。历史提交保留当轮截止时间。
- 节点从任务激活开始计时。转交保留原截止时间；会签共用截止时间，只提醒未处理人员；连续多级及依次审批各任务独立计时。抄送不单独计时。
- 到期前提醒、超时提醒、重复提醒间隔（0 为一次）、超时后指定督办人均可配置。督办通知仅开放该申请查看权限，不授予审批权限，并记录操作日志。
- 整单到期提醒发起人和当前未处理人员；节点提醒只通知当前未处理人员。退回后停止原节点提醒，整单继续提醒发起人。办结、拒绝、撤回停止提醒。
- 列表、工作台、PC/H5 详情展示时限，当前超时统计按整单或当前节点超时去重。超时不会自动同意、拒绝或跳过节点。
- 页面打开或恢复可见时、可见期间每 30 秒检查一次，将当前应发的提醒写入本地消息。关闭页面期间不执行后台任务；下次打开只补当前提醒，不补发每个历史周期。
- 多页面检查在 Web Locks 内进行并按计时轮次、提醒窗口、接收人去重；没有新提醒时不写存储。正式系统应改为服务端定时任务和消息队列。
- 已有浏览器数据不自动重置、不改写发布版本或在途申请。旧版本只保留原有节点时限；节点和提醒变更需编辑、发布后用于新申请。新建事项沿用整单 72 小时、节点 24 小时默认值。

### 流程与高级配置闭环

- 节点支持人工审批、自动通过、自动拒绝；空人时阻断、交管理员、交指定人、自动通过或拒绝。指定自选范围在提交时校验，仅命中节点要求选择处理人。
- 节点字段权限：可编辑、只读、隐藏；修改重新校验、记录日志，但不重写已确定的路由和人员。计算/流水号/附件等不开放节点编辑。
- 会签、或签、依次审批；节点独立转交/退回开关、意见必填及意见模板、时限；加签会等待新增审批人。
- 高级页支持在途撤回期限、催办、发起人自审和重复人规则、全局审批意见/加签/转交/退回、自动标题与摘要、最多 10 个数据权限组。
- 权限组区分查看和导出，不授予审批权。摘要、详情及打印遵守字段可见性。配置保存、版本发布、冻结快照、重提与本地消息使用同一引擎。
- 已移除“表单 AI 能力”“填写提醒”“打印模板”高级页面；旧配置仅保留兼容，申请详情的普通打印仍可使用。

### 尚未实现或尚未接入

- AI、OCR、电子签、外部联系人、行业通讯录、发票、客户、收款账户、预算、合同、工程项目均展示接入说明；没有伪造业务数据或调用外部接口。
- 本地尚无并行分支执行、审批矩阵、投票审批、自动化动作编排、连接器、网银付款、分栏布局或业务控件组套件。
- 高级设置尚无审批通过后的撤销/修改、评论撤回、代人提交、任意节点退回、手写签批强制规则、工作日历、付费打印模板编辑器。

## 文件与隔离

- `entry.js`：挂载新菜单和独立 iframe，处理全屏抽屉；根页面只新增一行脚本引用。
- `engine.js`：纯审批规则与生命周期逻辑，可在 Node 直接测试。
- `form-model.js`：24 类字段定义、值计算、格式校验与公式解析。
- `oa-designer.js` / `oa-designer.css`：表单管理、三栏设计器、基础/高级设置、节点配置与视觉样式。
- `oa-settings.css`：高级设置分行布局、摘要/成员选择、权限卡片和节点抽屉规范。
- `oa-runtime.js`：动态控件、级联、签名、填写/打印预览、字段权限与加签交互。
- `timing.js`：整单/节点计时、时限校验、超时判断与按接收人去重的提醒。
- `seed.js`：独立演示组织、事项、申请和通知。
