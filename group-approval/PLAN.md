# 集团审批产品架构与原型开发计划

## 产品目标与边界

在根 index 菜单新增集团审批，覆盖总部行政与各公司业务审批。表单、流程、找人、办理、追溯由系统内部配置。保留客诉模块全部文件及存储；新模块采用独立样式快照、代码、命名和存储。钉钉仅作为未来身份与通知渠道，原型不请求钉钉接口。

## 信息架构

1. 审批工作台：待办、我的申请、常用事项、通知。
2. 审批列表：待我处理、我已处理、我发起、抄送我的、权限内全部；筛选、分页、导出、详情。
3. 规则配置：审批事项、分类管理；基础信息、表单设计、流程画布、运行设置、模拟预览、版本历史。
4. 组织与人员：公司主体、集团组织、员工身份、岗位任职；内部员工关联多个外部身份。
5. 审批统计：按时间、公司统计量、办结率、耗时、超时、类型分布、处理人负载。
6. 移动端演示：工作台、发起、列表、申请详情、审批办理、消息、我的；与 PC 共用数据和引擎。

## 核心模型

- Company / Department / Person / Appointment：公司归属与汇报关系分开，集团管理树跨主体，岗位按公司或集团范围匹配。
- Template：基本信息、字段 schema、节点树、运行设置；草稿独立于已发布版本，发布生成不可变历史版本。
- Request：内部单号、申请主体/部门/发起人、表单值、流程版本快照、解析后的任务、操作事件、修订轮次。
- Task：审批/办理/抄送，指定人/部门负责人/连续负责人/岗位/直属上级，支持会签、或签、顺序签。
- Notification：接收人、关联申请、类型、已读状态。

## 关键规则

表单和流程必须联动；条件分支按优先级首个命中，必须有默认分支。申请冻结发布版本；退回修改使用本次版本重新路由。空负责人默认阻断，可配置承接人。申请人自审、重复审批人按显式配置处理。权限在引擎中检查，不只隐藏按钮；管理员不能代替未授权审批人审批。多人审批/返回/撤回/转交均留痕。浏览器内使用独立存储、revision 与 Web Locks 防止同源多窗口覆盖。

## 示例事项与场景

用印、采购、报销、请假、业务优惠、付款六类；包含草稿、审批中、办理中、已办结、退回修改、拒绝、撤回、超时；跨公司逐级审批、大额条件、会签/或签/依次审批。统一采用集团审批管理员视角，保留仅重置本模块的入口。

## 原型与生产分界

本地原型展示可运行规则、界面权限与交互；不能承担服务端鉴权、跨设备同步、真实钉钉身份校验、消息推送或银行付款。附件演示限制大小并保存在本地。生产组织主数据应接入现有组织与人员，不建立重复主数据源。
