# 客诉工单原型使用说明

2026-09-29 统一办理流程 V3。当前支持普通服务与一般退款闭环。详细流程与验收见 [统一办理流程 V2](../客诉工单系统_统一办理流程与实施验收_V2.md)。

## 页面结构

- PC：客诉工单、规则配置。配置仅对主管开放。
- 员工 H5：工单列表、新建工单、工单详情。员工填写、跟进、登记履行和回访。
- 钉钉独立任务页：通过具体任务链接审批或登记财务结果。只允许该任务办理人操作，已完成或失效的任务只能查看。
- 本期没有客户 H5。工单负责人联系客户，记录意见、沟通依据及附件。
- 处理方案、审批、退款凭证、回访、历史记录均保留在同一工单中。
- 演示入口默认显示全部页面入口和各办理人的任务，不设身份切换；时间推进和重置集中在入口页。

## 业务流程

普通服务：受理分派 → 接单 → 联系与处理 → 400回访 → 结案。在统一表单中可以保存多次跟进，或一次提交真实解决内容和客户同意依据。需要补做服务时，先生成执行任务，实际履行后才回访。无需独立品控满意度确认。

一般退款：联系与处理 → 提交本版退款方案 → 审批 → 负责人记录本版客户意见 → 财务执行 → 结果成功 → 400回访 → 结案。审批驳回、客户不接受均返回处理；结果未知只能核查，确认失败后才能重试。审批等待和财务执行各自计时，不计入处理人的办理段。

接单须明确点击；打开详情不接单。未接通仅记录首次尝试，不冒充首次有效联系；保存跟进必填下一步和下次跟进时间，不能重置处理期限。已接单的工单可由主管 / 受理员安排交接，保留前任用时与原截止时间，接替人重新接单。

“限时办理与超时提醒”替代原来的“SLA时效驱动”。每个任务显示办理人及截止时间；超时提醒不会自动结案。

规则配置首页为场景列表，默认提供一级、二级、三级、四级客诉，可新建、查询、启用或停用场景。点击每行“配置”后进入三个页签：基本信息、审批流程、处理规则。审批流程沿用参考审批模板编辑页的画布：申请人卡片、连线加号、审批与抄送节点、金额条件分支、默认分支、节点复制删除、侧边配置抽屉及50%至150%缩放。处理规则沿用参考审批编辑器的分组表单：人员异常、重复审批、整单时限、节点时限、退款分支时限及办理提醒。人员异常与重复审批使用行内单选项，备用职责条件展开；每个节点的超时选项可就地展开编辑。正常派单不在每个场景重复配置，审批节点的时限与画布节点对应。四个初始场景为可修改的样例，并非最终业务制度。

PC 与员工 H5 新建工单时选择启用的场景，按该场景派单、计时与审批。保存配置只对新工单生效，已有工单保留受理时的场景版本与配置期限；流程界面按V3合并办理。停用场景不会删除已有工单。

## 组织与审批

规则配置内提供“客诉场景、审批人员”两个页签。审批人员页按公司职责展示组织部门、任职岗位及当前匹配人员，配置职责时选择部门与岗位，不直接勾选姓名。人员异常的备用审批人同样通过组织职责匹配，不逐门店指定姓名。

画布节点支持指定部门负责人、连续多级部门负责人、指定上级、连续多级上级、公司审批职责；部门起点可选工单门店或申请人任职部门，支持从下往上、从最高层计数及空负责人向上查找。多人办理支持会签、或签、依次审批。金额分支按优先级匹配，未命中走默认分支。抄送到达节点时产生通知及工单记录，不阻塞审批。

流程配置在受理时保留，审批人员在提交退款方案时按当前组织任职匹配并记录快照；普通组织调整不改写已有匹配快照。新规则的在途人员离职、任职失效或有效代办会产生有记录的交接；无法接替时生成管理员异常待办，维护有效任职后重新匹配恢复。提交前发现无法接替的缺人、层级不存在、循环关系或本人自审时阻止提交。

组织与任职目前使用本原型的样例数据和浏览器存储，尚未接入真实钉钉组织接口或主后台组织页面的数据服务。参考页面本身没有被修改。

## 本次处理规则重构（2026-09-29）

- 直接打开 [一级场景处理规则](http://127.0.0.1:8765/complaint-prototype/index.html?view=pc&actor=manager#rules/scene-level-1/handling)。编辑页刷新后保留场景及页签，未保存值不自动保存。
- 人员异常支持缺人／失效时暂停或按备用职责接替、申请人自审代审、连续重复审批沿用；有效代办优先。备用职责失效或匹配本人时不能自动同意。
- 整单从受理到完成400回访，按自然时间计算。初始场景一级24小时，二至四级72小时；已有保存的场景保留自己的数值，不覆盖用户配置。
- 节点规则按左侧分组标题、右侧字段与输入项排列，明确岗位、起点、完成条件、时限和超时动作。审批条件分支仅到达时计时；抄送不计办理时限；普通服务无需进入退款分支。当前仍支持服务和一般退款，赔偿专项业务没有因本次配置重构而自动实现。
- 节点期限不再被整单期限截短。服务与财务从执行任务生成计时；服务按规则期限与对客承诺较早时间办理，财务对客约定日期作为另一项承诺保留；财务提交、核查和重试共用本轮付款期限。未接通登记下次联系但保留原任务截止时间。
- 临期只提醒一次；到期按节点选择提醒本人或同步直属上级。接单可自动转派一次，仍无人接单交主管安排。整单超时单独通知总负责人及客诉主管。
- 工单详情内展示“办理时效与责任记录”，查看各人收到任务、截止、完成／转交时间、耗时和超时；无需新增菜单。
- 原型打开时每30秒检查提醒，刷新／推进演示时间也会检查。页面全部关闭期间没有后台推送服务，重新打开时补查。
- 已有工单保留旧日期、截止时间及历史记录，当前联系 / 方案 / 客户意见待办统一办理。旧品控待办取消并保留为只读记录，转400真实回访，不自动结案。

## 原型边界

数据保存在同一浏览器、同一来源的 localStorage 中。身份参数仅用于角色模拟；生产环境需要服务端权限校验、钉钉免登和任务链接鉴权。没有接入真实钉钉通知、订单或支付服务，不发生真实退款。赔偿及其他专项流程尚未实施。

已有示例工单保留；旧客户确认待办迁移给负责人，保留原任务编号、期限和方案版本。旧客户 H5 链接显示入口不可用。
