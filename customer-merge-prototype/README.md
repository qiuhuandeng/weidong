# 客户档案合并与纠错交互原型

基于三份客户档案规则文档与《客户档案合并原型开发计划》实现。门店端采用手机布局，不设置“合并与纠错总览”模块。

## 打开方式

优先打开 [demo.html](demo.html)。这里可以选择端口、业务场景，并查看完整页面地图。默认采用功能演示模式，所有端口均无需切换角色。

也可以双击 [启动原型.command](启动原型.command)，它会启动本地静态服务并打开演示入口。关闭终端或按 `Control+C` 停止服务。

原系统入口为 `index.html → 四、数据中台 → 客户档案合并`。现有客户、订单列表补充了对应的合并纠错记录入口；店长工作台工具箱新增“客户合并纠错”；集团审批增加业务工单及功能演示入口。

## 页面范围

| 端口 | 入口 | 页面视图 | 业务范围 |
| --- | --- | ---: | --- |
| 总部 PC | [pc.html](pc.html) | 32 | 合并管理、合并记录、纠错工单、财务处理、规则配置、运行与审计，以及关联客户与订单 |
| 门店手机 | [store.html](store.html) | 20 | 手机号核验、开单与排客、合并申请、纠错申请、协作、历史与消息 |
| 移动审批 | [approval.html](approval.html) | 7 | 合并审核、纠错审批、冲销加签、调整单确认与审批记录 |
| 客户小程序 | [client.html](client.html) | 5 | 手机号授权、换绑、会员中心、本人订单与详情 |

共 64 个页面视图，24 类共享浮层。页面编号和标题由 `page-manifest.js` 统一维护。演示入口另提供 22 个可重置的业务场景，不计入业务页面数量。

## 功能演示方式

- 所有表单可留空提交，空白内容、日期、对象与附件采用示例数据，无需准备材料。
- 同一个入口可以办理审批、资产核查、数据处理、身份拆回、调整确认和规则发布，无需切换账号。
- 已有纠错或合并申请时，直接进入已有记录继续演示。
- 纠错页面可以直接点击“数据处理完成，继续”，未逐项确认的内容采用默认归属并生成演示结果；最终确认一次完成财务与门店节点。
- 规则配置可直接保存、试算和发布，无需先完成试算。
- 页面上的风险、冷静期、身份及审批路径用于展示业务设计，不作为演示操作的前置门槛。

建议从“发起纠错申请”开始，提交后依次体验审批、快照、数据、身份、调整单与完成。也可以从页面地图直接进入任一步骤。

## 交互与数据

四个端口在同一浏览器来源下共享 `localStorage`，保留演示中的单据、附件、草稿、规则版本和操作记录。多窗口提交时读取最新数据。重复提交优先复用已有记录。

“载入场景”和“重置全部演示数据”仅重置本原型的数据。原系统其他模块的数据不受影响。

## 实现结构

| 文件 | 用途 |
| --- | --- |
| `seed.js` / `scenarios.js` | 一致的初始数据、22 个业务场景 |
| `walkthrough.js` | 功能演示适配、表单示例补齐、一键审批与非阻塞流程 |
| `engine.js` | 规则判定、快照、合并、纠错、冲销、身份恢复、确认与审计 |
| `app.js` / `styles.css` | 路由、端口外壳、事务、共享组件、弹窗基础与响应式布局 |
| `views-pc.js` | 合并、记录、财务、客户和订单页面 |
| `views-correction.js` | 纠错九页及跨端共享处理组件 |
| `views-rules.js` | 规则七个配置页签、试算、版本、清洗与审计 |
| `views-mobile.js` | 门店、移动审批、客户小程序页面 |
| `dialogs.js` | U-01 至 U-24 浮层与操作 |
| `entry.js` / `host-adapter.js` | 原系统、店长工作台及集团审批的轻量入口适配 |

## 验证说明

原有 `engine.test.cjs` 和 `qa/browser-test.cjs` 描述早期的严格规则流程，不作为当前功能演示的操作要求。当前应检查空表单可提交、已有工单可继续、同一账号完成纠错、移动端开单以及无需试算即可发布规则。

## 原型边界

这是本地前端业务原型，使用模拟客户、订单、审批和财务数据。手机号授权、短信、定时任务、财务记账、外部身份平台均为模拟；没有连接生产服务。集团审批使用入口适配，保留其原有管理员身份和数据模型，未将两套审批引擎合并。新增客户与订单视图使用本原型的数据集，通过原列表入口访问。

功能演示适配允许补齐和跳过前置步骤，不构成生产环境的鉴权或财务事务保障。投入实际系统时需要服务端权限、身份验证、流水账本、任务队列及接口对接。
