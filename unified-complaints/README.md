# 统一客诉交互原型

入口：根目录 `index.html#unified-complaints`，菜单「统一客诉 → 投诉处理」。独立预览为本目录 `index.html`。根页面仅加载本模块脚本，原有客诉功能保持不变。

## 状态与操作

列表顶部为「全部 / 待处理 / 处理中 / 已完成」tab，与搜索区合为一张卡片，点击直接切换。保留独立工单状态列与客诉等级列，操作列仅有「详情」。处理、编辑处理方案、跟进及结案均从详情进入。搜索沿用当前 tab，重置清空条件并保留当前 tab。

按本模块要求，「待处理」「处理中」tab 名称后显示括号数量，包含当前搜索条件下的全部匹配记录，不受分页和当前选中状态 tab 影响；零条显示 0，处理、结案后同步更新。「全部」「已完成」不显示数量。

列表字段没有值时统一显示「—」，不显示「待填写」「待判定」「未定级」「未关联」等文字；有值的工单状态正常显示。

「投诉 / 渠道」列顶部仅显示投诉时间，不显示单据编号；编号仍保留在详情、搜索匹配及导出中。

| 工单状态 | 详情内容 | 底部操作 |
| --- | --- | --- |
| 待处理 | 处理方案仅展示「暂未处理」，不铺开空字段 | 处理 |
| 处理中 | 已保存处理信息，处理结果为未解决，继续沟通 | 写跟进、结案 |
| 已完成 | 处理结果为已解决，保留处理及结案记录 | 关闭 |

「处理」表单仅包含客户反馈、处理信息和「处理结果」，关联订单移至详情公共资料区独立管理。处理结果为必填下拉框，首次处理默认「请选择」：选择「已解决，立即结案」后点击「提交并结案」，一次保存处理信息并结案；选择「未解决，继续沟通」后保存，进入处理中，之后可以继续跟进或单独结案。责任部门、售后类型、责任人、客诉等级和处理结果均为必填，缺失时在字段旁提示并定位到第一项。其余字段和订单关联不增加阻断校验。

处理中工单的「处理方案」tab 提供整体编辑入口。修改方案仍在独立「处理」抽屉进行，客户反馈和处理信息整体带出、一次保存，不提供分块编辑，也不会改写公共区的订单关联。处理中改选已解决可直接结案。已结案工单的处理方案只读，不显示编辑入口，也不能再次进入处理或修改方案。

## 抽屉

### 投诉详情

详情只读。tab 上方为公共客户资料区：姓名、电话与状态为首行，渠道、时间、单号、发起人合并为紧凑元信息；投诉文字使用完整行宽，图片在第二行横向排列，与正文左侧对齐。关联订单表格放在其下，模块右上角提供「关联订单 / 调整订单」入口。下方为「处理方案」「跟进记录」两个 tab；切换 tab 不切换订单。公共资料与内容使用同一滚动区，tab 滚动到顶部时吸顶，抽屉标题及底部按钮固定。

尚未处理时，处理方案 tab 仅显示「暂未处理」，不显示空白字段、结果卡片或编辑入口，使用抽屉底部「处理」。已处理后，用同一张卡片包住客户反馈和处理信息，内部以分隔线组织。取消卡片顶部独立结果栏，处理中才在「责任认定」标题右侧显示「编辑」，仍打开完整处理表单；已结案隐藏编辑。客户反馈包含首次联系人、联系时间与客户陈述；处理信息包含责任部门、售后类型、责任人、等级、责任原因和处理结果。底部统一显示处理人、处理时间及结案时间。

跟进记录按实际发生的阶段展示处理、沟通、修改方案和结案。历史沟通内容可以通过独立编辑抽屉修改，保留原时间、当时状态、责任快照和修改历史。无操作记录 tab，内部日志继续保留。

### 微信支付渠道资料

微信支付投诉在列表的投诉摘要下显示订单金额、申请退款金额。详情在投诉内容下方、关联订单上方直接展示「微信支付信息」：商户名称与商户号、微信投诉单号与投诉时间、外部单号与客户昵称、问题类型与问题描述、订单金额与申请退款金额。微信投诉状态单独标注；微信支付订单号、投诉次数和风险状态放在「更多支付资料」展开查看。其他渠道不显示此模块。

微信信息为只读渠道资料，与内部关联订单、客服选择的售后类型、工单状态分别保存。调整关联订单不会改变微信原始单号与订单金额；缺失金额显示「—」，真实零金额显示 ¥ 0.00。关键词可搜索微信投诉单号、昵称、商户名称/号、外部单号及微信支付订单号。已知模拟工单只补齐缺失的渠道字段，已有值、处理信息及历史保留；未知记录不自动补造渠道资料。

### 处理

860px 表单抽屉，保留双列短字段布局，窄屏使用全宽。分组与详情一致，按「客户反馈 → 责任认定」排列，处理结果放在责任认定末尾，不包含关联订单模块。

- 无订单也可直接填写和保存处理；订单核对、关联及人员追踪在详情公共区完成。
- 保留客诉第一联系人、联系时间、客户陈述，第一联系人以客户陈述为准。
- 保留责任部门、售后类型、责任人、客诉等级、责任原因和处理结果；部门先选、类型后选。类型包含闭店及约定的 19 项；等级为 1级、2级、3级、4级。
- 责任部门、责任人使用带箭头的下拉多选框，展开后勾选多个，已选项在框内显示；支持键盘和点击外部收起。两项均至少选择一个，售后类型与等级仍为单选下拉框。
- 类型规则仅作归因参考，不自动决定责任人，客服拥有最终修改权。
- 保存处理信息自动留痕，不要求重复填写一段跟进。保存采用完整草稿一次写入，失败时保留草稿。
- 「处理结果」下方提供「附件（选填）」上传，支持 JPG、PNG、PDF、Word、Excel 和 MP3、M4A、WAV、AMR 录音，最多 4 个，每个不超过 5MB。不上传也可提交；支持连续添加、移除、编辑回填和放弃草稿。保存后在处理方案及对应处理历史中展示，图片可预览，文档可下载，录音提供播放及下载，AMR 下载后播放；已结案只读。附件与原始投诉图片、跟进图片分开保存，修改附件不改写历史快照。

### 写跟进

680px 表单抽屉，仅包含跟进内容与可选图片，不提供处理状态选择。仅处理中可新增，空内容可直接保存，保存不会结案。历史跟进修改只影响该条内容和图片，不回滚当前责任、处理方案或工单状态。

## 订单关联与追踪

在详情 tab 上方的公共资料区关联或调整订单，点击进入独立订单选择抽屉。搜索、重置、选择、保存有效，最多两层抽屉。保存关联直接更新公共区及列表，记录操作日志，但不提交处理方案、不改变客诉状态。取消不保存，未保存选单变化有放弃确认；返回保留原 tab 及滚动位置。

订单选择支持到店日期范围及上月、昨天、今天、本周、本月快捷日期；关键词可切换客户手机、客户姓名、客户微信、会员号、订单号，并可按关联咨询姓名组合搜索。初始带入当前客户手机，日期不限；重置清空全部条件，查询可关联订单。客户微信使用客户自己的微信字段，与预约顾问微信分开。列表显示序号、客户姓名、会员号、客户手机、订单号、门店、咨询、状态和操作。点击「选择 / 取消选择」维护草稿，已选订单在列表下方集中展示并可移除，搜索或重置不清空已选项，保存后才更新关联。

公共资料区的订单使用精简表格：客户信息、预约门店、订单意向、服务项目、到店时间；订单号作为项目辅助信息。行内展开展示加微记录（含预约微信号）、推广、咨询、接待销售、项目接待、操作、店长。预约微信读取原有订单记录，缺失项显示未记录或待核实。

## 模拟数据与兼容

18 条初始投诉按状态分别提供模拟详情，覆盖三个渠道和 1—4 级。待处理记录有投诉、图片和订单，但无首次反馈、责任处理信息、处理方案及处理跟进记录；初始处理中模拟记录有完整处理方案及后续沟通；已完成记录有解决方案及结案信息，包含首次直接解决和沟通后结案两种情况。

补入三条新的待处理工单，分别来自客户小程序、移动工作台和微信支付，保留旧缓存中已手动操作的记录。新记录只加入一次，之后的实际处理状态不会被刷新重置。

旧缓存按版本执行一次状态适配：重新生成未手动操作的模拟记录；保留手动保存的内容、附件和历史，已保存完整责任信息的旧待处理记录调整为处理中。重复刷新不重复生成、清空或恢复已操作的数据。

责任部门和责任人的旧单值记录继续兼容；编辑时带入原选择，新保存采用数组，列表、详情、历史和导出统一显示多个值。部门筛选匹配任一已选部门。

本地数据保存在浏览器 `weidong.unified-complaints.v1`，未连接真实渠道、订单或员工接口，不向微信发送消息，不改变外部订单状态。工单状态属于当前投诉，微信协商记录只读。

投诉图片以缩略图展示，点击打开只读大图。模拟图片内部标注模拟资料，不添加「示例」文件按钮。已有附件保留。跟进图片上传支持 JPG/PNG，最多 4 张，每张不超过 5MB；处理附件支持的格式见上方「处理」说明。

## 验证

语法：`node --check unified-complaints/app.js`。

状态检查：待处理信息为空且只有处理入口；五项必填内容缺失时不能保存；已解决提交立即结案；未解决进入处理中并显示跟进及结案；跟进不会结案；已完成不再新增跟进，也不能编辑处理方案。

数据检查：三类状态内容匹配；旧缓存手动修改保留；版本适配幂等；跟进快照独立；仅详情入口可启动处理；状态 tab、搜索和重置保持联动。

交互检查：详情只读；订单在 tab 上方公共区独立管理；未处理方案显示空状态；处理方案统一展示、整体编辑；处理和跟进使用独立抽屉；选单与草稿保留；未保存关闭提示；处理结果切换更新提交按钮；固定页头页脚、列表状态、表格展开及实际布局。
